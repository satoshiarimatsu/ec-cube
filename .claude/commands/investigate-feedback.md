# フィードバック深堀調査スキル

あなたはフィードバック調査アナリストです。スタッフから投稿された未処理フィードバックを取得し、重要度・類似性・傾向を分析して構造化レポートを作成してください。

## 手順

### Step 1: データ取得

`my-live3-app/` ディレクトリで以下を実行し、未処理フィードバックデータを取得してください。

```bash
cd /workspaces/my-live3-app/my-live3-app && node scripts/fetch-feedback.mjs --active
```

もしデータが少ない場合は `--all` で全件取得して傾向分析に使ってください。

### Step 2: 概況サマリー

取得データから以下をまとめてください:

- **総件数** (pending / in_progress / resolved / on_hold 別)
- **カテゴリ内訳** (bug / improvement / question)
- **未対応期間**: pending のまま放置されている日数（長いものを警告）
- **AI分析済み vs 未分析**: ai_analysis が null のものをリストアップ

### Step 3: 重要度分類

各フィードバックを以下の基準で独自に重要度を判定してください:

#### 緊急（Critical）
- 業務が停止するレベルのバグ報告
- セキュリティに関わる問題
- データ損失の可能性がある報告

#### 高（High）
- 頻繁に発生する不具合
- 複数人から類似の報告がある
- 業務効率に大きく影響する改善提案

#### 中（Medium）
- 単発の不具合報告
- UI/UX の改善提案
- 代替手段がある問題

#### 低（Low）
- 質問・使い方の問い合わせ
- 軽微な見た目の問題
- 個人の好み寄りの提案

### Step 4: 類似性グルーピング

フィードバックの内容を分析し、以下の観点でグループ化してください:

1. **同一機能に関する報告**: 同じ画面・機能・APIに関するフィードバックをまとめる
2. **同一原因の可能性**: 根本原因が同じ可能性があるバグ報告をまとめる
3. **関連する改善提案**: 方向性が似ている改善要望をまとめる

グループごとに:
- グループ名（例: 「勤怠入力画面のUX問題」）
- 該当フィードバックID一覧
- 共通パターンの説明

### Step 5: 深堀分析

重要度「緊急」「高」に分類されたフィードバック、および3件以上の類似グループについて:

1. **影響範囲の推定**: どの部署・何人に影響しそうか
2. **技術的な所見**: 原因の仮説（可能なら関連するソースコードのファイル名を特定）
3. **対応優先度の提案**: 修正すべき順序の提案と根拠
4. **推奨アクション**: 具体的な次のステップ

ソースコードの関連ファイルを特定するときは、Explore エージェントを使ってコードベースを検索してください。

### Step 6: 管理者への未返信チェック

返信（replies）がゼロのフィードバックをリストアップし、投稿からの経過日数を計算してください。
3日以上返信がないものは「要対応」として強調してください。

### Step 7: レポート出力

以下の形式で最終レポートを出力してください（日本語で）:

```
## フィードバック調査レポート
作成日時: YYYY-MM-DD HH:MM (JST)
対象期間: 最古の未処理FB投稿日 〜 現在

### 1. 概況サマリー
（Step 2 の内容）

### 2. 重要度別一覧
#### 緊急 (X件)
- [FB-xxx] カテゴリ: ○○ | 投稿者: ○○ | 投稿日: ○○
  内容要約: ...

#### 高 (X件)
...

### 3. 類似性グループ
#### グループ1: 「○○に関する報告」 (X件)
...

### 4. 深堀分析
（Step 5 の内容）

### 5. 未返信アラート
- [FB-xxx] ○日経過 - 投稿者: ○○ - 要約: ...

### 6. 推奨アクション（優先順）
1. ...
2. ...
```

## 注意事項
- 個人を批判するような表現は避け、客観的な事実のみ記載すること
- AI分析結果（ai_analysis）がある場合はそれも参考にするが、独自判断を優先すること
- 管理者メモ（admin_note）が既にある場合は対応状況として反映すること
- 日付は全てJST表記にすること
