# セッション引継ぎスキル（Handoff）

あなたはセッション引継ぎの専門家です。現在のセッションで行った作業を整理し、次のチャットがゼロコンテキストでも即座に再開できるよう、**各ドキュメントを実際に編集・保存**してください。

---

## Step 1: 変更内容の収集

以下を**実行**して今回のセッション範囲を把握する:

```bash
git log --oneline -20
git status
```

- **未コミットの変更がある場合** → ユーザーに「コミットしますか？」と確認
- 直近コミットから今回のセッション作業を特定（前回handoff以降のコミットが対象）

---

## Step 2: MEMORY.md を実際に更新

**ファイル**: `/home/codespace/.claude/projects/-workspaces-my-live3-app/memory/MEMORY.md`

1. Read ツールで現在の内容を読む
2. 以下の観点で Edit / Write ツールで**実際に書き換える**:

| セクション | やること |
|-----------|---------|
| 進行中の作業 | 完了→削除 or 簡潔化、新規→追記 |
| 既知の問題 | 解決済み→削除、新規→追記 |
| バグ修正で気をつけること | 今回学んだパターン→追記（重複しない） |
| 環境固有の注意点 | 新しいルール・設定変更があれば追記 |
| スキル一覧 | 新スキル追加時→追記 |

**厳守**: 200行以内。`wc -l` で確認し、超えていたら古い完了済み情報を削除して収める。

---

## Step 3: PROGRESS.md を実際に更新

**ファイル**: `/workspaces/my-live3-app/my-live3-app/PROGRESS.md`

1. Read ツールで現在の内容を読む
2. Edit ツールで**実際に書き換える**:
   - 完了した項目: `[ ]` → `[x] (YYYY-MM-DD)`
   - 新たに判明した未完了タスク: 適切なセクションに `[ ]` で追記
   - 既存項目は削除しない（履歴として残す）

---

## Step 4: コミット＆プッシュ

Step 2-3 の変更を**実際にコミット＆プッシュ**する:

```bash
git add MEMORY関連ファイル PROGRESS.md
git commit -m "docs: セッション引継ぎ — MEMORY.md・PROGRESS.md更新

Co-Authored-By: Claude Opus 4.6 <noreply@anthropic.com>"
git push
```

---

## Step 5: 引継ぎサマリーをテキスト出力

最後に以下のフォーマットで**ユーザーにテキスト表示**する（ファイルには書かない）:

```
## 今回のセッション（YYYY-MM-DD）

### 完了した作業
- [コミットハッシュ] 概要
- ...

### 未完了・次回対応
- 項目と理由（なければ「なし」）

### 注意事項（次のセッション向け）
- デプロイ待ちの変更
- 次回最初に確認すべきこと
- 新たに発見した技術的注意点

### 更新したドキュメント
- MEMORY.md: (具体的な変更点)
- PROGRESS.md: (具体的な変更点)
```

---

## ルール

1. **全ステップを実際に実行する** — 手順の説明ではなく、Read/Edit/Write/Bash で実作業を行う
2. **コードの修正は行わない** — MD系ドキュメントの更新と情報整理のみ
3. **MEMORY.md は200行以内** — `wc -l` で確認。超えたら古い完了済み情報を削除
4. **推測で書かない** — git log と実ファイルを必ず確認してから更新
5. **未コミット変更への警告** — git status で変更があれば必ずユーザーに報告
6. **最後に必ずプッシュ** — ドキュメント更新のコミット＆プッシュまでが引継ぎ
