# フィードバック対応完了スキル

対応が完了したフィードバックのステータスを resolved に変更し、報告者に返信を送信する。

## 前提条件

- ユーザーからどのフィードバックを処理するか指示がある（ID、報告者名、内容のいずれか）
- 対応内容（何を修正したか、何を改善したか）がユーザーから伝えられている、または直前の会話コンテキストから把握できる

## 手順

### Step 1: 対象フィードバックの特定

ユーザーの指示から対象を特定する。必要に応じてデータを取得：

```bash
cd /workspaces/my-live3-app/my-live3-app && node scripts/fetch-feedback.mjs --active
```

対象のフィードバックIDと内容を確認する。

### Step 2: 返信文の作成

以下のルールに従って返信文を作成する：

#### 必須ルール
- **素人にも分かる言葉で書く**（技術用語は使わない）
- **謝罪は不要**（「申し訳ございません」「ご不便をおかけして」等は書かない）
- **感謝から始める**（「ご報告ありがとうございます」）
- **何が起きていたか** → **どう直したか** → **今はどう使えるか** の順で説明
- 短く簡潔に。長くても5〜6行以内

#### 文面テンプレート

```
{名前}様、ご報告ありがとうございます。

{何が起きていたかの説明（1〜2文）}

{どう改善したかの説明（1〜2文）}

{今後の使い方や確認方法（必要な場合のみ）}
```

#### 例

```
牛久様、ご報告ありがとうございます。ベルの上の❶が消えない件、修正いたしました。

ベルの中の通知とは別に、ホーム画面の「INFO」セクションにも未読の通知がある場合に残る仕組みでした。

現在は、ベルを開いた時に「INFOセクションに未読があります」という案内とリンクが表示されるようになっています。
```

### Step 3: ユーザーに確認

作成した返信文をユーザーに表示し、OKをもらう。修正の指示があれば反映する。

### Step 4: 実行

確認が取れたら、`my-live3-app/` ディレクトリで以下を実行：

```bash
cd /workspaces/my-live3-app/my-live3-app && node scripts/resolve-feedback-supabase.mjs "<feedback_id>" "<返信メッセージ>"
```

※ 返信者名義は**有松さん（既定・2026-10-06 指示「今後も有松がやる」）**。第3引数の admin_email を省略すればよい。
※ 旧 `scripts/resolve-feedback.mjs` は Postgres 直結で `SUPABASE_DB_PASSWORD` が必要だが .env.local に無いため使えない。上記の supabase-js 版を使うこと（処理内容は管理画面の返信APIと同じ: 返信追加 → 投稿者へ通知 → resolved 更新）。

**複数件ある場合は1件ずつ実行する。**

### Step 5: 結果報告

処理結果をユーザーに報告する：
- 対象者名
- ステータス変更（→ resolved）
- 送信した返信の要約

## 注意事項

- **対応済み・未対応が明確でない場合は必ずユーザーに確認する**
- 返信は1フィードバックにつき1通（重複送信しない）
- 類似フィードバックが複数ある場合は、それぞれの報告者に個別の返信を送る（コピペ禁止）
